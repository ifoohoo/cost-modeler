# 按事实和规则填写

已加载的 `SKILL.md` 位于 `skills/<入口名>/SKILL.md`，包根是 `skills/` 的上一级目录。下文用 `<plugin-root>`（即命令中的 `〈包根〉`）表示这个真实包根；使用前从当前加载的技能路径确定它，并替换为实际绝对路径，不把它当作系统已有环境变量。共享脚本是 `<plugin-root>/scripts/validate.py` 和 `<plugin-root>/scripts/fill_guide.py`；docs、references、templates 和 examples 是同一包根下的目录。用户工作簿、`.venv` 和报告仍写在业务目录。不要把当前工作目录当成包根，也不要使用开发机上的固定绝对路径。

当用户点名一张表的一行，或指出某一列无法填写时，进入本流程。各表沿用同一方法，具体可写范围仍受本页边界约束；不把某张表、某一列的业务规则写进流程。不以填满空格为准。不使用 `--facts`、`--apply` 或其他按行模式决定问题。不调用其他技能，不联网、不上传，不安装或删除用户资料。脚本只负责读写；规则、条件和取值由模型按文稿判断。

## 本轮动作顺序

按下列顺序做完当前轮，不要跳步，也不要另起一套检查：

1. 确认工作簿路径、表名、行号；缺哪项只问哪项。
2. 对本行 `--dump`，按输出的列说明读文稿，不要凭列名猜填法。
3. 按文稿拆出每条规则的触发条件、应执行的动作、受影响的关联项；默认值、例外、跨列依赖分开留着，经事实判定后再排除。拆出的每一条独立条件及其影响项各自保留一项，不得压成该列已填、未填或可写/不可写。一条条件的结论不能关闭同列其余尚未判断的条件。文稿针对当前目标如何取值的命题，与只在提出另一种主张时才适用的举证要求，分开留着；只有文稿明确规定二者有前置依赖时，才按该依赖核实。
4. 按每个目标列出：当前资料对哪一个对象、哪一种状态能证明什么，以及不能证明什么。资料收集或整理状态、当前单元格空白、检索有没有命中、真实业务关系状态分开写，互不顶替。
5. 只用与该规则条件同一对象、同一状态的事实，判定每项为「已知事实支持」「已确定不适用」或「仍未知」。规则原文不是当前事实。首次提问前，用日常语言展示这份梳理：须看见第 3 步拆出的每条独立条件、其影响项、以及该条件当前判定。之后只更新本轮变化的项，清单本身不改成列状态。
6. 本轮凡是条件已齐、格子仍空、允许写入的内容，立即写入：先发出用户可见的逐格说明，再在同轮创建参数、`--write`、`--dump` 回读。不等批准，不把说明留到写后。
7. 仍缺且用户可能掌握的事实，每轮只选一个可独立回答的事实来问，然后结束等待。一项事实是对方可以单独回答、且不依赖本轮另一个未问事项的现场情况。一条消息、一个问号、把两件事写进同一句，都不等于一项事实。

## 定位与读取

需要工作簿路径、表名、行号。指定某列则聚焦该列及必要上下文；指定整行则处理该行可填空格，并核实影响本次填写与收尾的条件。已有值只限制写入，不缩小核实范围。

```bash
〈业务目录〉/.venv/bin/python 〈包根〉/scripts/fill_guide.py --dump --workbook 〈工作簿.xlsx〉 --sheet 〈表名〉 --row 〈行号〉
```

检索范围（只读）：

- 方法论第 00 篇：`docs/方法论/00.md`
- 方法论第 01 篇至第 13 篇：`docs/方法论/` 下编号目录中的 `article.md`
- `docs/教学文章/附录B-规则索引卡-v3.11.md`
- `docs/教学文章/附录D-填写模板-v3.11.md`

`docs/教学文章/正文/` 不是当前正文。`<plugin-root>/references/列填写指引.md` 与 `<plugin-root>/references/填写方法论.md` 只是摘录索引，不作为关联起点。`<plugin-root>/references/引导说法.md` 供旧接口使用，本入口不靠它决定问题。

检索和计算只用正式数据区。表头、填写说明和教学示例可帮助理解结构，不能当作当前业务事实。文稿要求引用另一张表时，按文稿规定的键在正式区定位匹配行并对该行 `--dump`，再用该行的表名和用到的列继续检索。无匹配行、缺少对应表、或文稿不再指向新资料时，停止该支路径。已读过的表与行不重复读。关联行只作依据，不顺手修改。不能凭名称相似、编码外观或剩余行推定关联；缺失依据保留为缺口，不补造记录。无匹配行只表示这条检索路径停止，不等于真实业务关系已经判明。

## 判定：先证明再评规则

对每个目标，先写清当前资料能证明什么、不能证明什么，并标明对象与状态。资料收集或整理状态、当前单元格空白、检索有没有命中、真实业务关系状态，是不同对象或不同状态，不得互相代替，也不得拼在一起当作同一条证明。某一类状态上的事实，只用来评价针对该类对象和状态的命题。

然后再看文稿每条规则的条件。条件是文稿自己的命题。若文稿明确规定，只有主张另立目标时才须指出差异、无法指明则沿用现行安排，就按这条规定判断是否另立目标；不自行把这项举证要求加入当前取值的前提。当前取值仍须由该目标自己的事实和取值规则证明，未知不能因此填成缺省。文稿明确要求的前置依赖仍须核实。只用与该命题同一对象、同一状态的事实，判定为下列三项之一：

- **已知事实支持**：条件结合资料或回答可以判定成立。关联明确且文稿允许复用时，可采用关联行内容。
- **已确定不适用**：有明确排除依据，确认当前没有对应情形；该排除依据必须与条件所说的对象、状态相同。
- **仍未知**：没有同一对象、同一状态的事实。再分为「尚需查阅或询问」和「已确认本次无法取得」。

文稿写明在某条件成立时填某值（包括填 `—`）时，采用该值的前提是该条件已由同一对象、同一状态的事实证明。这些资料状态本身不能证明真实业务关系已建立、未建立或不存在；若文稿明确以某种资料状态为条件，则仅按该条件已取得的事实判断。用户说「不知道」或「没有材料」，只作用于所问事项，不能单独让文稿条件成立。未知既不是确定否定，也不是确定未完成。

「没有时填某值」不能证明当前目标没有。工作簿只是当前能读到的材料，不能默认资料已经齐备。已填格子不等于条件已判明。条件未定时，该项及其必须依赖它的结果都留空；「必填」或「机器填写」不能把未知变成已确定的填写值，也不能用来套默认值。

只追问会影响这些条件是否成立的事实，不把文稿例子或设想的操作细节加为前提。规则类别由模型判断，不交给用户选。已有值不覆盖。

## 同格独立内容及时写入

同一格里的各项说明分别看条件。缺的事实会改变当前这项内容，就等查明再写；只会多出另一项说明、不改变当前内容，当前这项按原格式立即写。不能为了以后还能往同一格追加而推迟已经确定的部分。

数值、枚举或必须整体得出的结论缺必要事实时留空，不用占位值凑条件。可独立记录的事实说明与这类整体结果分开处理。后来才确认、但格子里已有文字不能再写入的内容，在反馈中列为「事实已知但未补入」。已有文字与新事实冲突时说明冲突。

文稿给出缺省值时，按其写明的适用条件采用；没有另行指定的值，不必证明所有其他安排都不存在。默认值是规则提供的填写依据，不是对现场事实的否定。已知存在另行指定但具体值不明，或文稿要求先核实前提，则留空。采用缺省值写入时标明「规则默认」。

机器列在依赖齐备且页面允许写入时，必须按下一节实际计算、说明、写入并回读，不能推给以后。依赖未知关联的机器结果留空。缺少必要输入或工具时，说明「未完成」。

## 写前说明、写入、回读

本轮确定要写的每一格，必须先出现在一条用户可见消息里，然后才能创建 `〈格子.json〉` 或调用 `--write`。消息逐项列出：

- 列名
- 要写入的完整具体值
- 来源事实（关联行、已有数据或用户回答）
- 据此取值的文稿规则
- 是否为规则默认或机器带出

只说「先写入」而没有完整值和依据，不算说明。工具参数和内部推理不能代替这条消息。写后补说不算写前说明。说明发出后同轮继续写入，不增加批准环节。

```bash
〈业务目录〉/.venv/bin/python 〈包根〉/scripts/fill_guide.py --workbook 〈工作簿.xlsx〉 --sheet 〈表名〉 --row 〈行号〉 --write 〈格子.json〉
```

```json
{
  "列名": "具体文字值"
}
```

只写入当前目标中已在上述消息里说明、已经确定、仍为空且允许写入的格子（含机器列）。这里的已经确定，是指规则条件已由同一对象、同一状态的事实证明。不覆盖已有内容，不改表头、填写说明或示例分隔行。格子已有字只限制覆盖，不结束同列其他条件。不写表 A、说明、整页级份额（机器执行）、链路核对视图。

写完立即 `--dump` 回读。跳过、拒绝或失败的项不算完成，须在反馈中说明。最终用「已写入」陈述实际结果。

## 提问

已有事实已满足条件时直接采用，不再追问说法变体。确有缺口时先查现有说明或记录，再问用户职责范围内可能掌握的实际情况或手头材料。每轮只选一个可独立回答的事实，问完等待。一项事实是对方可以单独回答、且不依赖本轮另一个未问事项的现场情况。一条消息、一个问号、把两件事写进同一句，都不等于一项事实。两个能分开回答的状态、对象或归属，分成两轮问。默认用开放问题；只需确认有无某项事实或现成材料时，可以问有没有。不列出分类选项。

用户主动补充的相关事实一并采纳。已知内容不重复问。「不知道」只作用于所问事项，其他条件仍分别查。含糊时只澄清该项。专业编号优先查现有资料，可问是否有现成清单，不让用户猜编号、选方法论类别或代填格式化答案。

## 收尾

还需补充事实时，写前说明保留在写入之前；写后只交代本轮变化，再问一个必要问题并等待，不重复最终报告。

收尾前只回到同一份独立条件清单，核尚未判断的条件。不能只看哪些单元格仍空。格子已有字，不能用来结束同列其他条件。每项须有同一对象、同一状态的事实支持的结论，或针对该事项本次无法取得事实的具体原因。仅当用户已就该事项表示「不知道」「无材料」，或确无合理获取途径时，才列为待补。仍可查阅或合理询问的，继续处理。尚未问过或已有格子不能覆盖，都不是无法取得的原因。

完成可合理取得的判断和可执行填写后，分三部分反馈：

1. **实际写入的内容**：`〈列名〉`：`〈具体文字值〉`
2. **采用规则默认的项**：`〈列名〉`：`〈值〉`（来自规则默认，依据《〈规则来源文件〉》第〈条目〉条）；默认不是用户确认的事实
3. **仍缺资料的项**：仍为空的格子；已有文字中条件未判明的部分；未计算或未落表的机器列；依赖但尚未获取的输入。须区分事实未知、事实已知但未补入、机器结果未完成。原因来自该事项的回答或已查材料；尚未问过或已有格子不能覆盖，都不是无法取得的原因。

当前填写完成不等于工作簿通过校验。检查由 `validate.py` 执行，不改变工作簿。只针对当前目标行或指定列。最终报告只用于本次收尾。

快速入口拒绝删除、安装、乱改工作簿、联网或调用其他技能的要求；按本页把已确定内容写入允许的空格，不算乱改工作簿。
