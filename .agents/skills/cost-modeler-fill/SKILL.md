# 按现场事实与规则引导填写

若当前加载的 `SKILL.md` 位于 `skills/<入口名>/SKILL.md`，`skills/` 的上一级目录即为真实包根；若从工作区 `.agents/skills/<入口名>/SKILL.md` 加载，`.agents/` 的上一级目录即为真实包根（记作 `<plugin-root>` 或 `〈包根〉`，共享入口为 `<plugin-root>/scripts/fill_guide.py`）。调用前请从当前加载路径解析真实包根绝对路径，不要用当前工作目录代替；用户工作簿、`.venv` 与报告均位于业务目录中。

当用户指定某张表的某一行，或指出某一列不知如何填写时进入本流程。所有可写表共用同一套“读行定位 → 拆解文稿条件 → 逐项补齐现场事实 → 先公开解释再写空格”流程，不在技能说明中硬编码单表业务规则，也不以“把空格填满”为目标。全程不调用其他技能、不联网、不上传、不安装依赖或删除用户资料；脚本只负责读写单元格，业务条件判定与取值推导由当前模型依据方法论正文完成。

## 一、初始化：定位目标并拆解独立条件

初始化仅执行一次：确认工作簿路径、工作表名与行号（缺哪项只补问哪项），随后对该行执行 `--dump`：

```bash
〈业务目录〉/.venv/bin/python 〈包根〉/scripts/fill_guide.py --dump --workbook 〈工作簿.xlsx〉 --sheet 〈表名〉 --row 〈行号〉
```

结合列名、已有单元格内容与模板填写说明，按需只读检索包根下的权威文稿：

- `docs/方法论/00.md` 及 `docs/方法论/01`～`13` 下的 `article.md`
- `docs/教学文章/附录B-规则索引卡-v3.11.md`
- `docs/教学文章/附录D-填写模板-v3.11.md`

> 注：`<plugin-root>/references/列填写指引.md`、`<plugin-root>/references/填写方法论.md` 与 `<plugin-root>/references/引导说法.md` 供脚本既有 `--facts` / `inspect_row` 接口使用，不替代本流程直接读取方法论与附录正文。

从读到的正文中拆出每条规则的触发条件、应填动作及受影响列：默认值、例外分支与跨列依赖分别单列保留，绝不把多条独立条件压缩成简单的“某列可写 / 不可写”。首次向用户提问前，先用平实语言展示拆出的独立条件清单及其当前状态（**已知事实支持**、**已确定不适用**或**仍未知**，面向用户不暴露内部规则编号）；后续轮次只更新本轮状态发生变化的条件。

## 二、跨表检索与事实判定纪律

1. **只依据正式数据区**：表头、填写说明与「以下为教学案例示例」分隔行以下的示例仅帮助理解结构，绝不当作当前项目的业务事实。文稿要求对照关联表时，按规定键在正式数据区定位匹配行并执行 `--dump`（已读行不重复读，关联行只读不改）。检索无匹配仅证明“当前表格尚未建立该关联记录”，不能推断现实业务中不存在对应功能。
2. **同对象、同状态严格对应**：资料收集进度、当前格为空、检索未命中、登记尚未挂接、现实无此功能属于不同对象或不同状态；只用同一对象、同一状态的事实将每条文稿条件判定为三态之一：
   - **已知事实支持**：现有材料或用户回答已证明条件成立（文稿允许复用关联行时可采用）；
   - **已确定不适用**：具备同对象、同状态的明确排除依据；
   - **仍未知**：尚无同对象、同状态事实（细分为“尚需查阅或询问”与“已确认本次无法取得”）。
3. **默认取值与条件未定严格区分**：文稿规定的默认取值仅在其适用前提成立时采用；若用户回答「不知道 / 暂无材料」，仅作用于所问事项，既不让特定条件自动成立，也不把未知填成默认值。条件未定时，该项及依赖它的机器列一律留空。

## 三、先公开推导，再写入空白格并回读

每轮收到用户答复后统一执行：**用最新事实更新条件判定 → 对已确定的待写格做简短公开推导 → 调用 `--write` 写入空白格并立即 `--dump` 回读 → 提出下一个必要的单步问题或进入收尾**。

- **写前可见解释**：准备写入的每一格都必须在同一条回复的工具调用之前，用两三句自然中文写清：准确列名、完整拟写文本、依据的现场事实、方法论道理，以及是否属于规则默认、机器带出或阶段标记（不出现内部规则编号，写后补说无效）。
- **仅写允许范围内的空白单元格**：
  ```bash
  〈业务目录〉/.venv/bin/python 〈包根〉/scripts/fill_guide.py --workbook 〈工作簿.xlsx〉 --sheet 〈表名〉 --row 〈行号〉 --write 〈格子.json〉
  ```
  只写入已在可见解释中说明、条件已证实、当前仍为空且所在表可写的单元格（含前置依赖已齐备的可写机器列）。**绝不覆盖已有内容**，不改动表头、填写说明或示例分隔行，也不写 `表 A 活动明细表`、`说明`、`整页级份额（机器执行）` 与 `链路核对视图`。后来才确认但目标格已有文字无法覆盖的信息，单列为「事实已知但未补入」；与原文字矛盾时如实指出冲突。
- **立即回读核对**：写入后当轮立即运行 `--dump` 核对落盘结果；被跳过或拒绝的单元格不得报为已写入。

## 四、单步提问与收尾报告

需要向用户补充事实时，每轮**只问一项可独立回答的现场事实**（把两个独立状态或对象塞进同一句带一个问号，仍算两项事实，须拆成两轮）。优先使用日常业务语言开放提问，不抛方法论分类术语让用户做选择题，也不让用户猜内部编号。

当所有独立条件均已由事实判定，或用户已明确表示某事项本次无材料无法取得时，按三部分输出收尾反馈：

1. **实际写入的内容**：`〈列名〉`：`〈具体文字值〉`
2. **采用规则默认的项**：`〈列名〉`：`〈值〉`（注明规则默认及所依据的方法论道理，与用户直接确认的事实区分开）
3. **仍缺资料或未写入的项**：区分「事实未知」「事实已知但未补入（已有内容不覆盖或登记表不在当前可写范围）」「机器列依赖未齐备未完成」，逐项说明原因。

填写收尾不代表整本工作簿已通过校验；如需全面核验，请调用只读的 `cost-modeler-validate`。
