# 运行环境检查与准备

若当前加载的 `SKILL.md` 位于 `skills/<入口名>/SKILL.md`，`skills/` 的上一级目录即为真实包根；若从工作区 `.agents/skills/<入口名>/SKILL.md` 加载，`.agents/` 的上一级目录即为真实包根（记作 `<plugin-root>` 或 `〈包根〉`，共享入口为 `<plugin-root>/scripts/setup_check.py`）。执行命令前请从当前技能路径推导真实包根，不要把当前工作目录当作包根；用户工作簿与 `.venv` 均位于业务目录中。

## 先检查，再决定是否安装

诊断阶段全程只读，不自动安装依赖，不改动工作簿，也不触碰已有的虚拟环境。在目标业务目录下执行（`--root` 指向业务目录）：

```bash
〈业务目录〉/.venv/bin/python 〈包根〉/scripts/setup_check.py --root 〈业务目录〉
```

若业务目录尚无 `.venv/bin/python`，可用系统 `python3` 运行同一脚本获取诊断结果。脚本依次核查三项条件：

1. 业务目录下是否存在 `.venv/bin/python` 解释器；
2. 该解释器能否成功导入 `openpyxl`；
3. 包根下的共享脚本 `validate.py` 与 `fill_guide.py` 是否齐全。

三项全部满足时打印「就绪」并退出 `0`，无需重复运行。

## 缺项时的计划与确认要求

一旦缺少 `.venv` 解释器或无法导入 `openpyxl`，脚本只输出以下三步计划并以退出码 `2` 结束，不会自行执行安装：

1. 复用业务目录已有的 `.venv`（仅在不存在时新建，绝不重建已有环境）；
2. 在该 `.venv` 中安装 `openpyxl`（已能正常导入的版本保持不变，不因存在新版而升级替换）；
3. 重新运行 `setup_check.py`，确认三项条件全部通过。

**必须等待用户明确同意后**，才按上述计划执行安装。若检查提示包根入口脚本缺失，属于插件安装不完整，不能靠重装 `openpyxl` 解决，请先核对宿主插件安装目录。

## 能力边界

未经用户明确同意绝不安装依赖；全程不修改业务工作簿，也不改动校验规则。
